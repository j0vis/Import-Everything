== Description ==

An independent, original importer for everything a source can hand you — XML, RSS, Atom, JSON, CSV and Google Sheets — in one three-step visual workflow. Upload a file or connect a public feed or sheet, explore the discovered schema, map fields, preview records, and import through WordPress APIs. The admin screen is built as a single premium workspace: no nested settings pages, no separate modules to buy.

Features:
* Detects item, entry, record, photo, video, gallery, media, post, article, url, and page records, plus RSS/Atom channel and feed containers.
* Reads JSON feeds too: records are discovered as arrays of objects, nested objects become slash-separated field paths, arrays of values become repeated fields, and a top-level array is read as the record list. XML, RSS, Atom, JSON, CSV and Google Sheets all use the same mapping, preview, history, saved-feed and batch pipeline; the format is detected from the file's content, not its extension.
* Reads CSV and TSV tables: the header row becomes the field names, so one line is one record and every column maps like an XML element. Commas, semicolons, tabs and pipes are detected from the header row (blank lines above it are skipped, and a separator inside a quoted value does not count), a UTF-8 BOM is stripped, blank header cells are named `column_N`, and a repeated header name gets a numeric suffix instead of two columns sharing one path. A short row fills its missing cells with empty values and extra cells past the header are ignored, so a ragged export still imports uniformly.
* Reads Google Sheets: paste the normal sheet link (or a published-to-web link, including the `/spreadsheets/u/0/` form an account copies from its own list) and the import reads that sheet's CSV export, keeping the tab named by `gid` in the link, whether it sits in the query or after the `#`. No API key, no OAuth and no service account are involved; a sheet that is not shared or published is refused like any other private address.
* Scans EVERY selected record for fields, including attributes, nested elements, CDATA, namespaces, empty fields, and repeated values.
* Distinguishes NATS named item groups such as item[@id="ids"] and item[@id="ident_details"].
* Searchable field explorer, dropdown mapping, click-to-map, and drag-to-map.
* Map post title, content, excerpt, featured-image URL, categories, tags, and arbitrary standard WordPress post metadata.
* Categories and tags are mapping targets of their own. Every value of the mapped field becomes a term, and a value holding commas lists several (`News, Sport`), so an RSS feed's repeated `<category>`, a JSON array of tags and a CSV or Google Sheets column all work the same way. Names are trimmed, de-duplicated and capped at 50 per record, and a term that does not exist yet is created — the normal WordPress behaviour for an importer. A taxonomy the chosen post type does not register (pages carry neither categories nor tags by default) is refused with a message instead of importing nothing.
* One-click WP-Script preset: fills WP-Script's own video fields from the feed — `video_url` (the two-line join when the feed splits it), `duration` converted to the whole seconds their themes expect, the hover preview under `trailer_url` — WP-Script's own key — with `preview_url` written beside it for a feed or theme that names the field the other way, `embed`, `shortcode`, `tracking_url`, `hd_video`, `likes_count`, `dislikes_count`, `post_views_count` and `thumbs`, the mouse-over slideshow their cards play when a video has no trailer, stored as one meta row per image — including frames the feed splits across numbered fields (`screen_1`, `screen_2`, `screen_3`) or lists in one cell separated by commas, semicolons, pipes, line breaks or spaces, the per-quality `video_url_240` … `video_url_4k` files their player switches between and the `thumb` poster their listings read when the feed ships them (a quality is recognised under the `video_url`, `video`, `mp4`, `url`, `file` or `flv` prefix, with or without a `p` suffix, and a trailer is never taken for `video_url`) — plus categories, tags and the Actors taxonomy, and switches the target to the Videos post type when it exists. Fields the feed does not have are counted and reported, never guessed — except `hd_video` (`on`) and the three counters (`0`), which are written as fixed values because their themes expect a value there and no feed would carry one for you. Compatible with the WP-Script themes built on those fields (FamousTube, KingTube, KolorTube, RetroTube, TikSwipe, UltimaTube, VTube).
* One-click Tube Corporate preset: for the partner feed that tube family serves (`https://<site>/api/videos_feed2.php?csv_columns=id|title|description|duration|link|embed|embed_url|main_screenshot|preview_url|dir|categories|tags|models|is_hd|video_viewed|rating|video_url|screenshots`) — pipe-delimited CSV the importer already reads as it is — the same WP-Script video fields, filled from the family's own column names: `id` as the identity, `title` and `description`, `main_screenshot` as the featured image and the `thumb` poster, `duration` in seconds, `video_url` (joined to `dir` when the file is relative), `preview_url` under both `trailer_url` and `preview_url`, `embed`, `video_viewed` as the view count, `screenshots` as the `thumbs` gallery, and `categories`, `tags` and `models` as Categories, Tags and Actors — and it switches the target to the Videos post type. `is_hd` and `rating` are left alone on purpose: their themes read `hd_video` as the string `on`, and the two counters as percentages of one another, which neither a `1`/`0` nor a single rating can fill without arithmetic this plugin does not do; `hd_video` and the counters are still written as fixed values. Paste the feed URL on the source step and press Apply Tube Corporate preset.
* One-click NATS preset: fills the featured image, the two-line video URL, and the duration, model, and site rows from the fields your feed actually has, and tells you which recipe fields it could not find.
* Join two feed lines into one URL. Feeds like NATS keep a base directory in one element and the file name in another, and mapping either line alone gives a 404; a featured image or a custom field can be mapped to both lines and stores the complete URL. When the feed splits its video URL that way, the suggested video_url custom field arrives already filled in with both lines.
* Repeated custom values: first value, newline-joined string, or WordPress-serialized array.
* Posts, pages, image attachments, and eligible registered custom post types.
* Draft, pending, and publish settings for ordinary post types.
* Preview up to five records without creating posts or fetching media.
* Import identity plus unique record field for skipping/updating duplicates.
* Fixed values (`const:`) and `{field}` templates (`tpl:`) for categories, tags, Actors and custom meta, so a field a feed leaves empty can still be filled.
* Small batches, pause/resume, and JSON import reports. Each batch resumes from a private on-server record spool instead of re-reading the feed from the top, so a long import keeps a steady pace instead of slowing down as it goes. Every batch also stops on its own deadline inside your server's request time limit, with each image fetch capped by what is left of it, so a slow record cannot run the loop into the limit. If a batch finds the lock another request still holds, the browser waits the reported number of seconds and retries by itself. Records per batch is a number you type on the import step — any whole number from 1 to 100, 5 unless you change it — so a host with little memory can import one record per request instead of five, and a long feed can import a hundred per request instead of five — each batch is one request, so a 1000-record feed at 100 records per batch is ten requests instead of two hundred, and what a batch imports is what stays in memory until it ends.
* Import history: the last 20 runs are stored on this site with the feed name, record counts, results and the latest journal entries, so you can see what a past import did and resume an unfinished one after you close the tab. The history holds no feed contents, no sample values and no server paths, only the administrator who ran it can read it, and uninstall deletes it.
* A one-click support report bundling environment limits, the mapped settings, the current import journal, and diagnostics for failures that need no server access to diagnose.
* Saved feeds you can manage: save an analyzed feed, then rename it, point it at a new address, or open it to change its mapping, all from the Saved feeds list. Changing an address reads the new feed once and checks the saved mapping against it first, so a moved feed is not saved pointing at a document that no longer has its fields.
* Importing has its own admin menu entry, so the importer is one click from the sidebar instead of a page under Tools.
* Full documentation inside the plugin: a Documentation page linked under Import Everything! covers sources, field mapping, joins and positions, custom fields and presets, batches, saved feeds and schedules, limits, troubleshooting, security and what uninstall removes. It reads nothing from your site — no feed value or session detail is printed on it — so it works on a site with no internet access.
* Export/import mapping templates without feed URLs, credentials, or import session data.
* Administrator-only requests, nonces, per-user sessions, DTD/entity rejection, safe HTML, and public-only downloads with per-redirect checks that exclude private, reserved, carrier-grade NAT, and documentation/benchmark address ranges. Each hop's name is resolved once, and the connection is held to the addresses that check approved — a name that answers publicly to the check and differently to the connection is stopped before anything is read.

No third-party importer code, branding, libraries, or add-ons are included.

== Installation ==

1. In WordPress, go to Plugins > Add Plugin > Upload Plugin.
2. Choose import-everything.zip, install, and activate.
3. Open Import Everything! in the admin menu.
4. Upload an XML, JSON, CSV or TSV file, or paste a feed or Google Sheets URL.
5. Confirm the record element and review auto-suggested mappings.
6. Add custom fields using the exact meta key expected by your theme.
7. Choose post type, status, import identity, and duplicate behavior.
8. Generate a preview, confirm the checkbox, and import.

Requires XMLReader, DOM, mbstring, zlib, and normal WordPress HTTP/media support. Image resizing depends on your WordPress image editor. No Node.js or Composer dependencies are needed on your WordPress site.

== NATS mapping guide ==

Typical video feed:
Post title -> title (or @name)
Post content -> description
Featured image -> thumbnail
Unique identifier -> @id or adtoolid
Custom video_url -> url
Custom duration -> video_length
Custom model_name -> model
Custom site_id -> item[@id="ids"]/siteid

Some NATS feeds keep a URL in two lines: a base directory in one element and a relative file name in another. Mapping either line alone gives a 404, so map both — the base first, then the file name under "Then append" in the same row:
Featured image -> screen_url + clips/clip/screens/screen
Custom video_url -> clip_url + clips/clip/flv
A joined value is one URL, so its repeated-values mode must stay "First value". Auto-suggestions pair the two lines for you when the feed's image field holds a relative path and a base-directory field is present, and they add the video_url row above when a media line matches a base field by name — so a NATS video feed arrives with both lines mapped, aimed at the video_url key most themes read. Both lines show up in the field explorer like any other field.

Apply NATS preset (on the mapping step, next to Save mapping) fills that whole recipe in one click: the featured image, the video_url join, and duration, model_name, site_id, and site_name rows — each one taken from a field your feed really has, with the fields it could not find reported so you can add them by hand. It replaces the current mapping, so use it before you fine-tune rows.

For galleries, map a gallery URL to your theme's gallery_url key. Repeated photos/photo/url can be stored as an array, or select the nested photo record element to import one image attachment per photo. Choose the actual thumbnail field present in your feed.

A repeated-array custom field contains strings, not downloaded media IDs. Namespaced paths retain their prefixes. Empty and optional fields are still discovered. All values are text; numeric/date/ACF type conversion is not performed.

== Important behavior and limits ==

* Start on a staging site and back up before updating existing content.
* XML: at most 20 MiB per file, up to 20,000 selected records per file, up to 1,500 distinct field paths per feed, and a nesting depth of 48. Discovery also caps each selected record at 1 MiB before it is flattened; oversized records are rejected. File uploads additionally obey your host's PHP upload_maxfilesize/post_max_size limits; the UI shows the effective upload limit. For large files, increase host limits, fetch the feed by URL, or split it into smaller files. Storing the private session compresses the feed in bounded chunks instead of loading it whole, but a 20 MiB feed of poorly compressible content still peaks near 24 MiB of PHP memory while it is compressed, and writing that copy into the database briefly needs about four times the copy itself, so allow a memory_limit of at least 64M and more for a feed that does not compress. Starting an import also checks the feed, and the copy it stores, against the memory actually left under that limit, and refuses before it writes a session, a spool or a saved copy — telling you to import from a URL, split the file, or raise the limit — instead of failing part-way through the copy. Discovery lists every selected record, so very large feeds can be slow to analyze before import starts.
* JSON: the same limits as XML — 20 MiB per file, 20,000 selected records, 1,500 field paths, nesting depth 48, and 1 MiB per record. The document is read in chunks and one record is decoded at a time, so a 20 MiB JSON feed is never loaded whole. Keys become field paths (`meta/note`), `/` inside a key is escaped as `~1` and `~` as `~0`, null becomes an empty value, booleans become true/false, numbers keep their JSON spelling, and a key containing " + " is refused because that is the two-line join separator. JSON Lines/NDJSON and a document whose root is a scalar are not supported.
* Images: JPEG, PNG, GIF, WebP only; at most 10 MiB and 40 megapixels. Video downloads, full-gallery media downloads, SVG, AVIF, authenticated HTTP headers, FTP, and IPv6-only feed hosts are not supported.
* WordPress attachment records cannot have draft/pending status. Those selections become private; publish becomes inherit. Media FILE URLs themselves remain public under normal WordPress uploads; private status is not file-level access control. Existing attachment updates retain the original media file.
* A URL can be joined from exactly two feed lines, and only for the featured image and for custom fields. Both lines must exist in the discovered schema, the join is plain concatenation with no separator inserted, and the second line is only used in "First value" mode because a joined value is a single string.
* A repeated line can be read at a chosen position. Append `#2` (or `#3`, up to the number of values the feed held) to that part of the mapping, e.g. `screen_url + clips/clip/screens/screen#2` takes the second screenshot a feed like GetScoreCash sends instead of the first. The dropdowns list those positions as "value 2", "value 3"; the server checks the position against the schema's own value count, only the featured image and a First-value custom field may use one, and a record that carries fewer values than the chosen position leaves that field empty for that record. A field whose own name ends in `#2` — a JSON key can — is read as that field, not as a position, even when the feed also has a repeated `note` field that the position could otherwise mean; the shipped JSON sample (`examples/positions.json`) has exactly that pair, so the rule can be seen in one preview. That feed's `note` therefore offers no `value 2` entry: an exact path always wins, so the two cannot both be addressed under one name. Titles, content, excerpts, and unique identifiers stay single-field mappings. A suggested join is an ordinary row: it is added at most once, named video_url, only when its second line matches a base field by name and reads like a media file (a second line holding a picture is never used for it), and you can rename or remove it before importing.
* The NATS preset is a starting point, not a guarantee. It only uses fields your feed really has, matched by name against the recipe keys video_url, duration, model_name, site_id, and site_name, and it reports the recipe entries it could not find instead of inventing a meta key. A feed that names its performer or site fields differently gets no row for them: add one by hand with your theme's key.
* An empty response is reported as such. When a feed URL answers HTTP 200 with 0 bytes, the error names the host and says the dump was empty instead of calling it invalid XML. NATS adtools return an empty 200 when the selected filters match no records, or when the requesting server's IP is not allowed for that adtool key; open the same URL in a browser to confirm it returns XML, and pull the link from the adtool page itself so its key and filters are the current ones.
* Custom keys must start with a letter/number, contain only letters/numbers/dots/dashes/underscores, and be at most 191 characters. Protected keys beginning with an underscore are blocked. Advanced ACF repeaters/groups, plugin-specific field-key references, and taxonomies are not implemented.
* Content, excerpts, and metadata retain safe HTML only. Previews show it as text; frontend rendering is your theme's responsibility.
* Updating replaces title, content, excerpt, status, and mapped custom keys. Blank content/excerpt mappings clear those fields. Optional mapped meta fields missing from a record become empty (or an array containing an empty string). Unmapped custom metadata is preserved.
* Keep the SAME import identity and unique field on reruns. If no unique field is mapped, record fingerprinting is used: changed feed data then becomes a new record. Use a different identity for unrelated feeds, even if they share a domain. The identity a record is matched by is stored with the algorithm that produced it (`sha256:` prefix), and an upgrade rewrites the untagged identities an earlier release stored, once, so records imported before this release keep matching.
* Skipping never downloads an image. Updating retries image warnings and reuses a successfully imported unchanged image on the same post. Changing image URLs can leave earlier images in the media library.
* Failed images do not discard successfully imported posts; warnings appear in the report. A failed image in attachment mode fails that record. The latest 100 issues are kept in the report.
* Closing the tab no longer ends an import: the run is stored under Recent imports for 24 hours, and Resume continues it from the next record — including a record a killed request left half-written, which the journal names. The list keeps the 20 most recent runs, each entry is pruned 7 days after it was last touched, and an entry whose session has expired is listed as such rather than offering a Resume that cannot work; reload the source with the same identity and unique field to reconcile records that were already imported. Pausing waits for the active batch. A batch that finds another request holding this identity's lock waits it out and continues on its own.
* "Download support report" appears once a feed is analyzed and is generated by an authenticated request: your WordPress/PHP environment and size limits, the record path and counts, the mapped settings, the job counters and journal, and this import identity's batch-lock state (held, age, stale). It contains no copy of the feed file or its sample values. Tick “Include field names” beside the button and it also lists the field paths it discovered, names only — never a value — which is often what a support request needs to name the field that is missing. It describes an unexpired session, so download it while the session is open, and review it before sharing because journal entries can quote feed values.
* Feed data is compressed in private WordPress transients for up to 24 hours; sample values are not public attachments. Transients are not encrypted, can be evicted early by object caches, and expire through normal WordPress cleanup. Starting another import clears the previous completed session (its history entry stays). Uninstall removes this site's importer sessions, locks, spool files, import history, saved feeds, stored uploads and feed schedules, but preserves imported posts/media/matching metadata.
* While an import is resumable, its records also sit in a private record spool file in the server's temporary directory (about the size of the feed, e.g. ~17 MB for a 17 MB feed). It is not web-reachable, its path is never sent to the browser, and it is deleted as soon as the import finishes or its session is cleared. A job abandoned without finishing leaves its file for the server's temp cleanup, and the plugin also sweeps spools older than the 24-hour session window when it can list that directory.
* Imports are not transactional and have no rollback. Batches journal after each record. A batch imports 5 records by default (the import step sets 1 to 100) and stops on a deadline it computes from your server's time limit (and after 8 seconds of record work even when the server sets no limit), holding back 5 seconds so the record in flight can finish and the response can still be sent; it will not start a record with less than 2 seconds of that deadline left. Each image fetch is limited to what is left of the deadline, so a download that stalls fails on its own instead of the request being killed part-way through a write. A record that blocks inside WordPress itself (a very slow database query, another plugin's hook, or a long image resize) cannot be interrupted by PHP — the deadline bounds the fetches your server performs for this plugin and the number of records a batch starts, and the 5 seconds held back are what let that one record finish and the response go out. Each record is marked in flight before its writes: if the request is killed, the next batch says so in the journal, matches the record by its identity first, and continues — skip skips what landed and update completes it, so an interrupted import reconciles instead of re-creating records. The identity is part of the insert itself (`meta_input`), so a request killed mid-record is matched by the next batch instead of being duplicated; only a termination inside WordPress's own insert — after the post row exists but before its meta is written — can still leave a record to be re-created. A killed request cannot release its batch lock, so the lock is refreshed after every record and treated as abandoned once it has gone 2 minutes without a refresh; a lock inside that window is never stolen. While a lock is held the browser waits the reported number of seconds and retries automatically (up to 5 minutes) instead of stopping on an error.
* A saved feed can run on a schedule through WP-Cron (see below); an interactive import is not a background job, so resuming one still needs the Import Everything! page open in a browser. This release maps categories, tags and WP-Script's Actors taxonomy, not arbitrary custom taxonomies; it has no arbitrary XPath/PHP evaluation and no native adapters for specialized custom-field plugins. Excel workbooks (`.xlsx`) are not read directly: a spreadsheet has to arrive as CSV, which Google Sheets and every spreadsheet application export; the same goes for an Excel file saved as CSV. Reactive or push sources (NATS streaming subjects, webhooks) are read through the URL their server publishes, because an import is a pull, not a listener.
* Real browser/database tests used WordPress 6.8 with SQLite and WordPress 7.1.3 with MariaDB, both on PHP 8.5. A 20,000-record sample feed was imported end to end in each environment. Multisite, MySQL, and the minimum supported WordPress/PHP version matrix have not been verified. WordPress 6.8 itself emits PHP 8.5 deprecation notices in the local test environment.

* Saved feeds and schedules: when the latest run of a saved feed failed, opening the plugin screen says so at the top — naming the feed, when it failed and what the server said, with a button that opens Saved feeds — so a background failure is not something you have to go looking for. The Saved feeds list shows where each feed got to (its last run and result, including a failure message), when it runs next, and which post status its runs import with — Imports as drafts, pending review or published — so a feed's destination is visible without opening it. A scheduled or manual run reads a URL feed's document once more and checks the saved mapping against it before starting — the same check Save changes runs on a new address — so a feed that dropped a mapped field records one clear failure naming the feed and the field, starts no import and spools nothing, instead of importing nothing per record. An uploaded file's compressed copy is stored per administrator and can be deleted with its feed. The post status is chosen on the mapping step beside Save feed — and again on the preview step beside Import — and is stored with the saved feed, so its runs, scheduled ones included, import with the same status instead of always starting as a draft. Scheduled runs use WP-Cron, so they happen on page loads or when a system cron calls wp-cron.php; a scheduled run is not a live stream. A run that is paused, or still has records left, holds its feed's schedule until it finishes or its private session expires (one day). A pass is also bounded by your server's own `max_execution_time` — when that limit is under four minutes, the pass hands the remaining records to a follow-up event rather than being killed part-way through — and if a pass is killed anyway, the next scheduled run resumes that session from the record it reached; only when that session can no longer be read does the feed record a failed result explaining it and start fresh on its next schedule. Delete posts is permanent (not a trash), removes a featured image that the importer downloaded for the post, and cannot remove posts you lack permission to delete, which are reported. Posts imported by an earlier release are not linked to a feed until they are imported again.

== Changelog ==

= 1.3.2 =
The plugin is no longer packed by a separate build step: the folder in the repository is the plugin, and the release archive is an archive of that same folder, so nothing decides what ships apart from the plugin itself. Installing is copying or cloning the folder into `wp-content/plugins/import-everything/`, or uploading the release zip. No plugin behaviour changed, so there is nothing to migrate.

= 1.3.1 =
The 1.3.0 archive was built without one of the plugin's own include files, so activating it stopped with a fatal error before the plugin could load and no setting, post or saved feed was touched. The plugin folder is now self-contained: every file the plugin requires sits beside the main file, in the repository and in the release archive alike, and there is no packaging step to run or get wrong. Copying or cloning the folder into `wp-content/plugins/import-everything/`, or uploading the release zip, gives WordPress a complete plugin. No plugin behaviour changed, so there is nothing to migrate and no stored data to repair.

= 1.3.0 =
The plugin is now Import Everything!, and every name inside it says so. The folder and main file are `import-everything/import-everything.php`, the text domain is `import-everything`, the namespace is `ImportEverything`, the admin page is `import-everything`, and every stored name moved from `uxml_` to `iex_`: the version option, saved feeds, import histories, the saved batch size, the compressed copy of an uploaded feed, resumable sessions, per-record locks, the scheduled hooks, and the identity, image and feed meta of every imported post. An existing site is migrated once, in bounded chunks that resume on the next admin, AJAX or cron request instead of timing out, so saved feeds, schedules, histories and the identity of every imported post survive and nothing is imported twice. While the rename is still moving rows a duplicate lookup also matches the old `_uxml_identity` key, so an import that starts between two chunks cannot double up. The feed or Google Sheet URL field is back on the source step, beside the file upload under “or connect a feed or sheet”, so the Saved feeds tab lists saved feeds and nothing else. The optional field-name list in the support report is now called `field_names`, because `source.fields` in the same document is the count of fields. The WP-Script preset now fills Categories, Tags and Actors from the fields feeds actually use — including `<model>`, the element NATS keeps its performer in — and only for the taxonomies the target post type registers, so it cannot leave a mapping the preview refuses; anything it leaves out is named in the notice. It also fills WP-Script's `tracking_url` — one of the custom fields their Mass Embedder and Single Embedder write by default — from the feed's tracking field. WordPress identifies a plugin by its folder, so an existing install is deactivated and the new `import-everything` folder is activated in its place; the ZIP is now `import-everything.zip`. Importing now refuses a feed that cannot fit the site's `memory_limit` before any session or spool is written, with a message that names the memory needed and suggests a URL, a smaller file or a higher limit; the estimate is the 1.7× feed size the streaming copy measured, the same figure the gate's `PACK_MODE` arm reports, and the stored copy is checked at its own packed size as well, because writing it to the database serializes and escapes it again — a 20 MiB feed that compresses to nothing now hears that advice instead of running out of memory while it is saved. A scheduled or manual saved-feed run now validates the saved mapping against the document it just fetched, the same check Save changes runs on a new address: a feed that lost a mapped field records one failed result naming the feed and the field instead of starting an import whose every record fails, and the Saved feeds list shows that result beside the feed's next scheduled run. When a saved feed's latest run failed, the plugin screen now says so as soon as it opens — the feed, the time, the server's message and a way to Saved feeds — instead of waiting for someone to look there. A scheduled pass now stays inside your server's own `max_execution_time` rather than the four-minute ceiling alone, and a pass a killed request leaves behind is resumed by the next scheduled run instead of being skipped until its session expires. Every feed and image address is now resolved once, and the connection is held to the addresses that check approved: a name that answers publicly to the check and somewhere private to the connection is stopped before anything is read, instead of being followed to whatever a second lookup returned.

= 1.2.23 =
The gallery cell splitter now also separates images with pipes and whitespace, so a `thumbs` value written as `u1.jpg | u2.jpg` or `u1.jpg u2.jpg` still becomes one meta row per image. The absolute-URL guard covers the new separators too: a single image whose address carries a pipe, comma or semicolon in its query (`?q=a|b`) stays one row, and runs of whitespace count as one separator so an indented multi-line cell is read the way it looks.

= 1.2.22 =
A gallery cell that lists its images in one value can now separate them with semicolons or line breaks as well as commas — a spreadsheet export often writes a `thumbs` cell that way — and each address still becomes its own meta row, in the order the cell lists them. The same guard applies as for commas: a value is split only when every part is an absolute URL, so a single image whose address carries a comma or a semicolon in its query (`?crop=10,20`, `?a=1;b=2`) stays one row. The cell is split before HTML escaping, so the semicolon of an escaped `&amp;` entity is never mistaken for a separator.

= 1.2.21 =
A value stored as one meta row per item — WP-Script's `thumbs` slideshow among them — now also handles a feed or spreadsheet cell that lists the whole set in one value with commas between the addresses: each image gets its own meta row, in the order the cell lists them, which is how their cards read the slideshow. Only a value whose parts are all absolute URLs is split, so a single image whose address carries a comma in its query (`?crop=10,20`) stays one row instead of becoming two broken ones. The split happens in preview as well as import, so the preview shows exactly the rows an import writes, and it applies to the rows mode only.

= 1.2.20 =
The WP-Script preset now recognises the hover-preview clip under the name a feed or a theme actually uses — `preview_url` as well as `trailer_url`, and `preview` beside `trailer` — and writes it to both keys, so whichever one the site's theme reads finds the clip. Before this, a feed that called its hover preview `preview_url` had that clip imported as `video_url`, the film their player starts on, and `trailer_url` was reported as a field the feed does not have; a feed whose only playable clip is its preview no longer gets a `video_url` row at all, instead of a preview played as the film. The `thumbs` slideshow is still written from a repeated field or from numbered screenshot fields, one meta row per image, beside the preview keys.

= 1.2.19 =
Saved feeds and Recent imports now have tabs of their own instead of cards below the source step, where the saved-feed list and up to twenty stored runs pushed the source form down the page. The source step leads with the “From feed to WordPress” guide, which now sits above the source form instead of beside it, with its three steps side by side on wide screens. The Saved feeds tab lists the saved feeds and nothing else, and it is where a feed URL is entered. The Recent imports tab lists the same runs with a Refresh button and one line about retention instead of a paragraph, and resuming a run there puts the wizard back on its progress step. The source step no longer offers the “No feed handy?” sample buttons: the bundled sample feeds are still there for testing, but the step is the upload and the guide only. While the identity upgrade is still running, duplicate detection now matches both the tagged identity and the older untagged digest it is rewriting, so an import that starts between two upgrade steps cannot create a copy of a post an earlier version imported.

= 1.2.18 =
The one-time identity upgrade no longer rewrites every imported post’s identity in one statement, which could time out or hold a long lock on a site with tens of thousands of imported posts. It now works through the rows 500 at a time in `meta_id` order, and after every full chunk of 500 rows it records the identity it reached in the version option, so a request that runs out of time or is killed part-way leaves a marker that the next admin page, AJAX call or cron run continues from instead of starting the whole statement again. The plain version is written only once a read finds no untagged identity left, so an interrupted upgrade is still never skipped for good, and repeating a chunk after a failure changes nothing because a value that already carries its scheme is skipped.

= 1.2.17 =
The one-time upgrade check no longer runs on every page view. It reads the plugin header from disk to learn the installed version, and that read happened on public traffic that could never act on the answer. The check is now limited to requests that can use it — wp-admin pages, this plugin’s own AJAX endpoint and WP-Cron — so front-end traffic pays nothing, while the first admin page, AJAX call or cron run after an update still applies it before anything reads stored data. The header is also read once per request instead of once per check, which is what the support report and the upgrade check were both doing.

= 1.2.16 =
No behaviour change. The WP-Script preset’s video-file choice was tidied: a condition that could never be true was removed, along with the value it existed to read, and the commentary around the quality rows now says what the code actually does — a relative quality or file is joined to the feed’s only directory field when no name matches, and left out when several directories compete.

= 1.2.15 =
The WP-Script preset now fills the `thumbs` slideshow from feeds that give each frame its own numbered field — `screen_1`, `screen_2`, `screen_3`, or a `screenshot_*`, `image_*`, `pic_*` or `shots_*` family — instead of only from one repeated gallery field. The row the preset writes names every field of that family in numerical order, and the import still stores one `thumbs` meta row per image, which is how their cards read the slideshow; the order matches the feed's own numbering, blanks are dropped and URLs trimmed, and up to 12 fields are accepted. This uses a field list the server validates field by field, so a client cannot name a field this feed does not have. The mapping step names the extra fields under the row, and editing the row's field or mode turns it back into an ordinary single-field row.

= 1.2.14 =
The WP-Script preset no longer reports `hd_video` and the three view/like counters as fields the feed is missing. Their themes read a string there, so the preset now writes them as fixed values when the feed has no field for them — `hd_video` as `on`, `post_views_count`, `likes_count` and `dislikes_count` as `0` — and still maps the feed’s own field when it ships one, because real view counts say something a default cannot. The preset’s message says how many of the rows it wrote are fixed values. Nothing else is guessed: qualities, thumb, duration, trailer, embed, shortcode and thumbs still come only from fields the feed has, and the count it reports as missing now means exactly that. This uses the fixed-value rows from 1.2.12 (`const:on`, `const:0`), which you can also type yourself, and a feed with no actor or taxonomy data can likewise be filed under a fixed category or tag.

= 1.2.13 =
The support report can now include this feed’s field names: tick “Include field names” beside “Download support report” and the bundle lists the paths it discovered (`title`, `tags`, `clips/clip/duration`), so a support request can name the field that is missing or empty. It is opt-in and off by default, the list is built from each field’s name alone and never from the schema entry that carries its sample, and the server accepts only an explicit boolean, so a report that was not asked for field names cannot grow them. Field values, the feed file and the sample records are still never included, whether the option is on or off.

= 1.2.12 =
Categories, tags, Actors and custom meta rows can now be given a value of their own instead of a feed field. Type a fixed value (`Uncategorized`, or `on` for WP-Script’s `hd_video`) and it is written for every record; type a template such as `{site_name} - {title}` and it is built per record, with every `{field}` placeholder checked against the fields this feed actually has, so a template reads no more than a dropdown can. A feed whose `<tags>` element is present but empty can therefore still be filed under a fixed category, and a theme key the feed does not carry can still be filled. A fixed value may list several terms with commas, a template writes nothing for a record that fills none of its placeholders, and both show in the preview exactly as the import writes them. The mapping step disables the field picker while a value is typed, and the empty-field hint now distinguishes a field that is empty in every record from a template whose every field is, so a fixed value is never called empty. The stored mapping carries a `const:`/`tpl:` prefix, so saved feeds and mapping templates keep these values and the server validates them the same way it validates a feed path.

= 1.2.11 =
Every imported record's stored identity now carries the algorithm that produced it (`sha256:…`), and a site upgrading from an earlier release has its existing identities rewritten once, on the first request after the files change, so records imported before this release still match and are not imported again as duplicates. The plugin also records which version last ran its upgrade steps and only repeats them when that changes; the version is written after the steps finish, so an upgrade interrupted half-way runs again instead of being skipped for good. Saved feeds, import history, the batch-size setting and sessions written by 1.2.10 keep working untouched, and the regression gate now holds a frozen 1.2.10 fixture of those stored shapes and fails if a later release stops reading them.

= 1.2.10 =
How many records one batch imports is now a setting instead of a fixed 5. The import step offers 1, 5, 10 or 20 records per batch, saves the choice for the site, and the next batch uses it — which is the dial a small shared host needs, because each request holds only the records it imports, along with their meta, terms and downloaded images. The saved value is bounded on the server (1 to 20, anything else refused with its own message) and read per batch, so a value written into the options table by hand cannot make one request unbounded; the delete-posts pass uses the same size. The support report now shows the size in force beside its default and ceiling, and uninstall removes the setting. A mapping that points at a field the feed never fills — common with feeds whose `<tags>` element is present but empty in every record — is now called out once per field at the mapping step, naming every target that reads it, and the preview says which kind of empty it is (“empty in every record” or “none in this record”) instead of showing a bare dash that reads like a broken mapping. Automatic suggestions now cover Actors as well as categories and tags whenever the chosen post type registers that taxonomy, and switching to a post type that registers one fills the term targets the mapping still leaves empty — the mapping step comes before the post type picker, so a feed that carries performers could not offer Actors before, and a saved feed whose mapping predated term targets stayed blank even on the Videos type. The WP-Script preset recognises a quality under any of its prefixes with or without the `p` suffix (`mp4_720p`, `file_480p`, `flv_1080`), never takes a feed's trailer for `video_url`, and joins a plainly named relative video file to the feed's directory field the way per-quality files already were — leaving it out when the feed has no directory to join, instead of storing a URL that cannot resolve.

= 1.2.9 =
The WP-Script preset now fills the per-quality video files their player switches between — `video_url_240`, `video_url_360`, `video_url_480`, `video_url_720`, `video_url_1080` and `video_url_4k` — and the `thumb` poster their listings read. Only the qualities the feed actually ships become rows, named the way their metabox names them (`video_480`, `480p`, `file_480`, `flv_480` and a bare `480` are accepted too), and only when the value is a playable file: a quality key holding a page URL or a screenshot is skipped rather than imported as a video. A relative quality file is joined to the feed's directory field, the way the featured image already is. `video_url` starts on the plain file when the feed has one, otherwise on the best quality it ships; `thumb` points at the same field as the featured image, or at the feed's own poster field when the image is unmapped.

= 1.2.8 =
The CSV reader's delimiter scan is back to its simpler quoted-run pattern: the doubled-quote variant that shipped in 1.2.4 chose the same separator on 55,986 generated header rows, so it carried no behaviour and is gone rather than kept as untested complexity. The case that matters is now asserted instead — a header with an escaped quote and commas inside one quoted name, `"a""b,c,d";e`, keeps its semicolon and its two columns (`a"b,c,d` and `e`), and a header like `"name, full";id` keeps its comma inside the name.

= 1.2.7 =
A clearer refusal when a source answers but has nothing to import. A dump that parses into an empty container — a NATS XML dump whose own filters match no videos, for example — now says so and names what the document holds ("its <videos> element holds <updated>") together with the export settings to check, instead of listing record tags the document never had. An address that returns a web page instead of a feed (a sign-in wall, a challenge, a private sheet) is named as a web page rather than reported as invalid XML. Both messages keep the same status and behaviour: nothing is imported and no feed is saved.

= 1.2.6 =
Two cleanups after a close read. A custom field stored as one meta row per value — WP-Script's `thumbs` slideshow — now skips blank cells and trims surrounding whitespace, so a feed with an empty screenshot cell no longer imports a row their cards render as a broken frame, and a padded URL still resolves. The confirmation checkbox keeps its filled checked state and tinted panel, with its styling reduced to the rules it actually needs; the panel tint lives in its own `:has()` rule, so a browser without `:has()` support simply shows the filled box and the tick, never an unstyled control.

= 1.2.5 =
Mapping Categories, Tags or Actors now tells you at the mapping step when the selected post type cannot store that taxonomy, instead of letting the preview refuse it two steps later with a sentence that did not say which post type or which terms were the problem. The post type list the plugin ships to the page now carries each type's registered taxonomies, the three term fields are handled as one family in the client, and the server's refusal names both sides: "Page cannot store categories. Choose a post type that registers that taxonomy on the next step, or leave this field unmapped."

= 1.2.4 =
A close read of the CSV and Google Sheets path. Blank lines above the header can no longer decide the separator (an export that opened with one used to read as a single empty column), a separator inside a quoted header value is not counted as a column break, and an empty file is refused with its own message instead of being reported as a header without rows. A record that cannot be read back out of the private import copy now stops the run with a message instead of being skipped, which would have shifted every later record by one. Sheet links copied from an account's own list (`/spreadsheets/u/0/d/…`) are rewritten to their CSV export like any other, a `gid` in the query is kept as well as one after the `#`, and an address carrying `format=csvx` is no longer taken for an existing export. The tab id is read with one pattern rather than parsing the whole query, so an odd pasted address cannot build an array out of it.

= 1.2.3 =
The "I have reviewed the preview" checkbox now shows its own filled state, so ticking it is visible instead of leaving an empty box that looked unresponsive. Its checked box is green with a white tick, and the confirmation panel tints with it. Behaviour is unchanged: the box still gates the Import button, and the Import button still enables as soon as it is ticked.

= 1.2.2 =
Added WP-Script compatibility. A new one-click preset fills the fields WP-Script's own themes read from a video — `video_url`, `duration`, `trailer_url`, `embed`, `shortcode`, `hd_video`, `likes_count`, `dislikes_count`, `post_views_count`, and a `thumbs` hover slideshow — from the fields the feed actually has, switches the target to the Videos post type, and reports the recipe fields this feed lacks. Durations are converted to whole seconds (`05:00` and `PT5M` both become `300`, and an unreadable value writes nothing rather than zero), `thumbs` is written as one meta row per image because that is how their cards read the slideshow, and Actors joins categories and tags as a mapping target. Custom rows gain two options for this: a value format (as in the feed, or duration to seconds) and a row-per-value storage mode.

= 1.2.1 =
Categories and tags are now mapping targets beside the title and content. A mapped field contributes every value it holds — a repeated RSS `<category>`, a JSON array, or a comma-separated cell from a CSV file or Google Sheet — and each name is trimmed, de-duplicated, capped at 50 per record and created when it does not exist yet. The terms replace whatever the post held, so a re-run with Update existing records reflects the feed's own list, and the preview shows the resolved names before anything is written. A taxonomy the selected post type does not register is refused when the mapping is saved, and mappings saved before this release simply read as unmapped.

= 1.2.0 =
The plugin is now Import Everything!, and it reads one more shape of source: separated-values tables. A CSV or TSV file (comma, semicolon, tab or pipe, detected from the header row) is analyzed like any other feed — the header row becomes the field paths, so the same mapping, preview, saved-feed and resumable batch pipeline applies — and a Google Sheets link is read through the sheet's own CSV export, keeping the tab named in the link, with no API key or sign-in. The admin screen was rebuilt visually around the new name: a gradient brand mark and premium badge, a card-based step bar, a single elevated workspace card, gold accents and a refined button and focus style, all scoped to the plugin screen. The shipped examples add `catalog.csv`, and the distribution zip is now `import-everything.zip`; the plugin folder and text domain stayed `ultimate-xml` until 1.3.0, so existing installs, saved feeds, histories and mapping templates kept working.

= 1.1.7 =
Opening a saved feed no longer drops a positional mapping: a saved `field#2` is kept when the feed still has that line and that value, and an exact field name still wins over the suffix. The admin page footer now reports the plugin's real version instead of a fixed 1.0. A bookmark for the old Tools page redirects to the plugin's own menu page instead of dead-ending. RSS 1.0 records auto-map their `rdf:about` identifier instead of falling back to a content fingerprint.

= 1.1.6 =
A new JSON sample, `examples/positions.json`, carries a key that itself ends in `#2` next to a repeated field of the same base name (`note` holds two values, `note#2` is a plain key). It pins the rule that a spelled-out field wins over the position syntax: the key maps and previews as its own value, through the JSON parser and the import endpoint, while `note` still reads its first value.

= 1.1.5 =
The importer is now its own top-level menu entry instead of a page under Tools. A saved feed can be edited in the Saved feeds list: rename it, or give a URL feed a new address — the new address is read once and the saved mapping is checked against it before it is stored, so a moved feed cannot be saved pointing at a document that lost its fields. Re-saving an opened feed's mapping no longer renames the feed back to its host, and “Open” is now “Edit mapping” so it reads as what it does.

= 1.1.4 =
Positional mappings were tightened up: a path the feed really has always wins over the `#2` syntax (so a JSON key ending in `#2` maps as itself), a schema saved before positions existed no longer refuses a position it cannot count, and the value position is parsed in one place instead of two.

= 1.1.3 =
A request that fails before the plugin answers now says which request it was, the exact admin-ajax.php URL it went to, whether an HTTP status came back, and whether the page and that address agree on https — so a network or mixed-content failure reads differently from a feed or mapping failure. A reply that arrives without JSON is reported with its status for the same reason.

= 1.1.2 =
A request the browser never managed to send is now explained in the plugin's own words instead of the browser's “Failed to fetch”: if an https admin page posts to an http admin-ajax.php it says the request was blocked as mixed content and points at Settings → General, and otherwise it says admin-ajax.php was unreachable (site stopped, blocking security plugin or extension, dropped connection) and that this is not a feed error.

= 1.1.1 =
A feed URL that answers HTTP 200 with an empty body is now refused with the host and that reason instead of a generic empty-file or invalid-XML error, which is what NATS adtools return when a dump matches no records or the requesting server's IP is not allowed for the key. A repeated line can be read at a chosen position (`field#2`): the mapping dropdowns list “value 2”, “value 3” up to the number of values the feed held, the server bounds the position against that count, and the featured image or a First-value custom field can use one — so a feed like GetScoreCash, which sends two screenshots per record, can import its second `<screen>` instead of the first. Auto-mapping and the NATS preset still emit plain first-value paths.

= 1.1.0 =
JSON feeds: upload or fetch a .json feed and import it through the same three-step workflow, limits, history and saved-feed schedules as XML. Records are discovered as arrays of objects, nested objects become slash-separated field paths, arrays of values become repeated fields, and the document is streamed one record at a time so a large JSON feed is never decoded whole. The format is detected from the file's first non-whitespace byte, so RSS and Atom keep working through the XML parser and a .json URL that serves XML is still read as XML, while the two-line URL join now applies to JSON fields too. JSON nesting (48), record size (1 MiB), field count (1,500) and record count (20,000) reuse the existing limits, and a key containing the join separator is refused with a clear message.

= 1.0.0 =
Initial release: secure XML discovery, visual mappings, preview, batched import, featured images, custom metadata, and mapping templates. Abandoned batch locks are reclaimed automatically, sessions are compressed in bounded chunks, malformed request fields are refused with a clear message instead of a server error, unexpected errors are logged rather than returned to the browser, and a downloadable support report captures environment limits, the mapped settings, the import journal, and this identity's batch-lock state. Large imports no longer re-read the feed from the top on every batch: the records are copied once into a private spool file and the bulk feed is kept out of the per-record checkpoint, which measured about 3x faster batches on a 20,000-record feed. A batch now stops on its own deadline inside the server's request time limit and caps each image fetch by what is left of that deadline, so a slow record cannot run the loop into the limit; each record is marked in flight before its writes and the batch lock is refreshed after every record, so a request killed mid-import is reported in the journal and resumed after one heartbeat instead of waiting out a fixed lock penalty, and the browser waits and retries a held lock by itself. Import runs are now recorded on the server: the plugin page lists the 20 most recent runs with their counts and journal, and an unfinished one can be resumed after the tab is closed for as long as its private feed session lives. A URL can now be assembled from two feed lines (a base element plus a relative file name), which is what NATS video and screen feeds need to avoid 404s; each line is still verified against the discovered schema, when that second line is the video URL it arrives as a suggested video_url custom field instead of a row you add by hand, and a one-click NATS preset fills the rest of the usual video recipe (duration, model_name, site_id, site_name) from the feed's own fields. Saved feeds: a feed can be saved with its mapping, whether it was analyzed from a public URL or uploaded as a file, and the plugin page lists your saved feeds (there is no fixed limit). A URL feed is read again on every run; an uploaded file is kept, compressed, in this site's database and runs without the original file. Run a saved feed to import with its mapping, and analyzing that URL again restores the saved mapping automatically. A saved feed can run on a schedule (hourly, twice daily or daily) through WP-Cron, as the administrator who saved it, and rechecks that administrator's import permission on every run. Delete posts removes the posts a feed imported, in every status, and keeps the feed, its mapping and its schedule, so a later run imports them again. A run stops with a message when a saved field is no longer in the feed.
